# 机器人（Playerbot）组队前、组队后与退组后的行为说明

本文档按"组队前（无队伍）→ 组队后（加入队伍）→ 退组后（离开队伍）"三个阶段，梳理 Pandaria 5.4.8 playerbots 模块中机器人的相关行为。涉及的核心源码文件位于：

- 接受邀请：`modules/mod_playerbots/src/strategy/actions/AcceptInvitationAction.cpp`
- 离开队伍 / 被踢出：`modules/mod_playerbots/src/strategy/actions/LeaveGroupAction.cpp`
- 主动邀请附近玩家 / 公会玩家：`modules/mod_playerbots/src/strategy/actions/FollowActions.cpp`
- 组队策略触发器：`modules/mod_playerbots/src/strategy/generic/GroupStrategy.cpp`
- 自动识别主人（master）、跟随策略切换：`modules/mod_playerbots/src/AI/PlayerbotAI.cpp`
- 跟随 / 逃往主人：`modules/mod_playerbots/src/strategy/actions/FollowActions.cpp`

---

## 一、组队前（机器人未加入任何队伍）

### 1.1 自由活动策略

机器人在无队伍状态下，行为引擎加载三套默认策略（`ResetStrategies` 负责初始化）：

- 战斗状态（`BOT_STATE_COMBAT`）：默认职业战斗策略（按职业区分）
- 非战斗状态（`BOT_STATE_NON_COMBAT`）：默认采集、打怪、休息、吃喝等常规策略
- 死亡状态（`BOT_STATE_DEAD`）：释放灵魂、复活等默认死亡策略

如果开启了实例副本专用策略（`AiPlayerbot.ApplyInstanceStrategies = 1`），还会根据当前地图 ID 加载副本专属策略。

### 1.2 主动邀请他人入队（随机机器人）

`GroupStrategy` 注册了两个周期性触发的邀请动作：

- `often` 触发器 → `invite nearby`（邀请附近玩家）
  - 配置 `AiPlayerbot.RandomBotInvitePlayer = 1` 才会启用
  - 扫描当前地图上同一阵营、视野距离内、未入队且无待处理邀请、无邀请屏蔽的真实玩家
  - 找到后若机器人无队伍则新建队伍并发邀请（`AddLeaderInvite + AddInvite`），已有队伍则必须是队长/助理且队伍未满才能邀请
  - 邀请成功后会通过 `TellMaster` 通知 "Inviting 玩家名"

- `random` 触发器 → `invite guild`（邀请公会成员）
  - 配置 `AiPlayerbot.RandomBotGuildNearby = 1` 才会启用
  - 要求机器人有公会，在同地图同视野范围内找到公会 ID 一致且无队伍、无邀请、无屏蔽的真实玩家后发出邀请
  - 同样通过 `TellMaster` 报告邀请动作

### 1.3 接收邀请准备

`GroupStrategy` 监听 `group invite` 事件 → `accept invitation`。即：只要机器人身上有 `GetGroupInvite()`，引擎就会自动触发接受邀请的动作。

接受邀请前会先做一次"自邀请"过滤：如果挂起的邀请组的队长 GUID == 机器人自己的 GUID（创建组时 `AddLeaderInvite` 导致），则直接清空邀请，不做任何处理。

## 二、组队后（机器人接受邀请加入队伍）

### 2.1 接受邀请流程

`AcceptInvitationAction::Execute` 执行以下步骤：

1. **防护检查**：无待处理邀请直接返回；自邀请（队长就是自己）直接清空并跳过。
2. **通过 opcode 同步入队**：构造与客户端格式一致的 `CMSG_GROUP_INVITE_RESPONSE` 包，调用 `WorldSession::HandleGroupInviteResponseOpcode`，由核心完成 `group->AddMember` 和队伍创建。
3. **修复跨地图线程上下文**：由于上述调用发生在地图更新线程中（`CurrentMap` 非空），而 opcode 内会 `BroadcastGroupUpdate` 遍历所有队员并 `ForceValuesUpdateAtIndex`，若队员在不同地图上会触发 `AddToUpdate invalid map` 断言，因此调用前临时将 `CurrentMap` 设为 `nullptr`，模拟网络线程上下文，调用后恢复。

### 2.2 设置主人（Master）

接受邀请成功后，立即绑定 master：

- 只有**随机机器人**（`IsRandomBot`）才走此流程（自定义 bot 不受此规则影响）。
- 直接从刚加入的 `bot->GetGroup()` 取 `GetLeaderGUID()`，再用 `ObjectAccessor::FindPlayer` 找到队长玩家对象。
- 若队长在线且能找到，调用 `botAI->SetMaster(groupMaster)`，日志输出 "AcceptInvitation: bot XXX now has master XXX"。
- 若找不到队长（例如队长正在切地图/离线），只记录 "COULD NOT SET MASTER - group leader not found"，随后靠下方的自动 master 修正机制补救。

### 2.3 自动修正主人（引擎循环里）

`PlayerbotAI` 的每次循环（`UpdateAIInternal → UpdateMaster` 相关逻辑，`PlayerbotAI.cpp` 第 970-1047 行）都会检查 master 是否仍合适，若不合适会重新选一个：

- 触发条件：当前 **无 master**，或当前 master 其实也是个机器人（不是真人玩家）且机器人已经在队伍中。
- 优先取 `GetGroupMaster()`（队长）作为候选。
- 若队长不存在或队长也是机器人，则遍历整个队伍的所有成员，找到 **第一个非 bot 的真人玩家**（`GetPlayerbotAI(member) == nullptr`）作为新 master；战场中会单独处理但当前分支默认关闭。
- 一旦选出新 master 且与旧 master 不同：
  - `SetMaster(newMaster)` 正式绑定
  - `ResetStrategies()` 清空并重新装载所有默认策略
  - `ChangeStrategy("+follow", BOT_STATE_NON_COMBAT)` 显式开启**跟随**
  - 若新 master 就是队长，机器人会说 `"Hello, I follow you!"`；否则随机打招呼 `"Hello!"` 或 `"Hi!"`

### 2.4 策略切换（非战斗）

`AcceptInvitationAction` 末尾显式调用：

```
ResetStrategies();               // 重置为默认的战斗/非战斗/死亡三套策略
ChangeStrategy("+follow,-lfg,-bg", BOT_STATE_NON_COMBAT);   // 非战斗策略上叠加
Reset();                         // 重置 AI 当前动作队列、下次检查延迟等
```

叠加的含义：
- **+follow**：启用跟随策略 → 机器人按阵型移动到 master 或指定目标附近
- **-lfg**：禁用随机副本排队 → 组队后不再自己排地下城查找器
- **-bg**：禁用战场排队 → 组队后不再自己排战场

此外，在**战斗状态**中，系统还会根据队伍需求开关：
- `dps aoe`：输出职业启用 AOE 多目标输出
- `tank assist`：坦克职业优先协助控制怪物（配合主坦拉怪）

### 2.5 跟随行为细节

非战斗状态的 `FollowAction`：

- 通过 `Formation` 对象决定目标是谁（通常是 master，也可以是"主人的目标"等 Value 派生目标）及相对位置。
- 若与跟随目标的距离超过阵型的最大距离，就自动移动到位；移动优先级：战斗中高于普通跑路。
- 若目标正在飞行、机器人已在引导施法、目标已死等特殊情况，则暂时不跟随。
- 若激活了 `move from group` 策略（如站位过密自动散开），则 `FollowAction::isUseful` 直接返回 false，让位给散开策略。

距离 master 过远且战斗压力大时触发 `FleeToMasterAction`：

- 距离 < `reactDistance * 3`：1/4 概率说 "I am close, wait for me!"
- 距离 < 1000 码：1/10 概率说 "I heading to your position."
- 距离更远：1/20 概率说 "I am traveling to your position."
- 每次执行后延迟 3 秒再检查，避免频繁刷屏。

## 三、退组后（离开队伍 / 被踢出 / 队伍解散）

### 3.1 离开队伍入口 `LeaveGroupAction::Leave(Player*)`

无论是主动退组、被踢出还是队伍解散，最终都会走 `Leave` 函数，行为如下：

1. **退组操作**：如果 `bot->GetGroup()` 存在，调用 `bot->RemoveFromGroup()` 从队伍中移除自己（注释掉的 `Disband` 不会解散整个队伍，只退自己）。
2. **清空 master**：仅**随机机器人**会 `SetMaster(nullptr)`，自定义 bot 会保留原 master。
3. **策略重置条件**：若原 master 本身是机器人（即存在"bot 跟随 bot"的链式关系），则调用 `ResetStrategies()` 清空所有策略后重新加载默认值，让 bot 回归完全独立；若原 master 是真人，则跳过此次重置（保留如辅助、buff 等策略）。
4. **AI 重置**：最后统一调用 `botAI->Reset()`，清空当前动作队列、下次检查延迟、临时状态等，使 bot 立即以自由形态重新决策。

### 3.2 被踢出 / 队伍解散的处理 `UninviteAction::Execute`

- 收到 `CMSG_GROUP_DISBAND`（队长解散队伍）：直接 `Leave(bot)` 自己退组。
- 收到 `CMSG_GROUP_UNINVITE_GUID`（队长踢出某成员）：先解析包体中被踢者的 `guid_low`，若被踢的是**本机器人**则执行 `Leave(bot)`，否则不处理（别人被踢不影响本 bot）。
- 其他类型的队伍消息（如转移队长、队伍设置变更等）不触发退组，也不重置 AI。

### 3.3 退组后回到自由活动

退组后 master 被清空且策略已重置，行为与"一、组队前"完全一致：

- 随机机器人重新参与 RandomPlayerbotMgr 的调度（定时随机化装备/天赋、定期传送到新区域、重新随机等级等）。
- 会再次触发 `invite nearby` / `invite guild` 主动邀请他人入队。
- 若被真人玩家再次邀请，仍会按 `accept invitation` 流程正常加入新队伍。

## 四、各阶段关键事件对照表

| 阶段 | 关键事件 | 主要代码位置 |
| --- | --- | --- |
| 组队前 | 加载默认战斗/非战斗/死亡策略 | `PlayerbotAI::ResetStrategies` |
| 组队前 | 定时邀请附近玩家入队 | `GroupStrategy → InviteNearbyAction` |
| 组队前 | 定时邀请同公会附近玩家入队 | `GroupStrategy → InviteGuildAction` |
| 组队前 | 监听邀请事件准备接受 | `GroupStrategy → group invite 触发器` |
| 组队后 | 执行接受邀请并同步入队 | `AcceptInvitationAction::Execute` |
| 组队后 | 临时清除 `CurrentMap` 避免跨地图断言 | `AcceptInvitationAction.cpp` opcode 调用段 |
| 组队后 | 随机机器人绑定队长为 master | `AcceptInvitationAction` 后半段 |
| 组队后 | AI 循环自动修正真人玩家为 master | `PlayerbotAI.cpp` 970-1047 行 |
| 组队后 | 开启跟随、关闭 LFG/BG 策略 | `AcceptInvitationAction` 末尾 + `ChangeStrategy` |
| 组队后 | 阵型跟随与距离检查 | `FollowAction` |
| 组队后 | 距离过远逃往主人、沿路喊话 | `FleeToMasterAction` |
| 组队后 | 战斗中开启 dps aoe / tank assist | `PlayerbotAI` 组合策略切换 |
| 退组时 | 主动退组：离队、清 master、重置策略 | `LeaveGroupAction::Leave` |
| 退组时 | 被踢出 / 解散：识别后执行 Leave | `UninviteAction::Execute` |
| 退组后 | 恢复为组队前的自由活动状态 | 与"组队前"共用同一策略集 |
